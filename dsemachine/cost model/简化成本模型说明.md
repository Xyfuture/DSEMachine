# 简化成本模型说明

这份文档说明我们在 DSE 中如何为 chiplet-based LLM 推理硬件估算成本。

目标不是做一个特别精确的商业报价模型，而是构建一个足够稳定的 `cost proxy`，用于在大量 design point 中比较相对成本高低，并和性能、功耗、面积一起形成 PPAC / Pareto 分析。

## 1. 模型边界

当前成本模型只考虑以下几项：

- 制造成本
- 封装 / 组装成本
- D2D / C2C 互连带来的面积与成本开销
- 良率带来的有效成本惩罚

当前暂不考虑以下几项：

- 测试成本
- NRE 摊销
- 过细的工艺步骤成本
- 过细的封装材料成本

因此，这个模型更适合做：

- 不同 chiplet 粒度之间的比较
- 不同工艺节点选择之间的比较
- 不同封装方式之间的比较
- 不同互连带宽配置之间的比较

## 2. 核心思路

我们把总成本拆成四部分：

```text
Total Cost Score
= Silicon Manufacturing Cost
+ Advanced Packaging Cost
+ Yield Penalty
```

在实际计算时，更推荐使用“良率修正后的有效成本”：

```text
Effective Cost
= (Manufacturing Cost + Packaging Cost) / System Yield
```

其中：

- 前两项表示“做出这样一个系统要花多少钱”
- `System Yield` 表示“最终能做成可用系统的比例”
- 良率越低，平均每个可用系统分摊到的成本就越高

## 3. 制造成本

制造成本用于表示不同 die 和 memory stack 的基础制造开销。当前模型中，D2D / C2C 互连硬件的成本不单独列项，而是通过它们对 `estimated_pim_logic_area` 和 `estimated_io_chiplet_area` 的影响吸收到制造成本里。

### 3.1 PIM logic die 制造成本

```text
PIM Logic Manufacturing Cost
 = estimated_pim_logic_area
* logic_process_cost_per_mm2
* PIM_chiplet_count
```

其中：

- `estimated_pim_logic_area` 为单个 PIM chiplet 中 logic die 的面积
- `logic_process_cost_per_mm2` 由 `logic_process_node` 对应的 CATCH `combined_*` layer 决定
- `PIM_chiplet_count` 为系统中 PIM chiplet 总数

说明：像 `pe_memory_controller_number` 这样的参数，会通过增大 logic die 面积来提高成本，而不是单独作为一项成本直接加入。

### 3.2 IO die 制造成本

```text
IO Manufacturing Cost
 = estimated_io_chiplet_area
* io_process_cost_per_mm2
* IO_chiplet_count
```

其中：

- `estimated_io_chiplet_area` 为单个 IO chiplet die 的面积
- `io_process_cost_per_mm2` 由 `io_process_node` 对应的参考 layer 决定

这里 D2D / C2C 接口的成本，主要通过 `estimated_io_chiplet_area` 间接体现：

- 更高的互连能力需要更多或更复杂的 serdes、PHY、switch、buffer
- 这些资源会增大 IO chiplet 面积
- 随后面积再与 `io_process_cost_per_mm2` 相乘，映射成成本

### 3.3 DRAM stack 制造成本

```text
DRAM Manufacturing Cost
 = PIM_chiplet_count
* dram_die_count_per_stack
* estimated_dram_die_area
* dram_cost_per_mm2
```

其中：

- `estimated_dram_die_area` 可以在当前 3D-stacked PIM 模板下近似取为 `estimated_pim_logic_area`
- `dram_cost_per_mm2` 可先参考 CATCH 中较接近的 memory layer，例如 `combined_hbm2_12nm` 或 `combined_hbm_7nm`

如果前期不想把 DRAM 成本建得太细，也可以继续使用更简单的容量驱动模型，但需要在实现时保持和模板口径一致。

### 3.4 制造成本汇总

```text
Manufacturing Cost
= PIM Logic Manufacturing Cost
+ IO Manufacturing Cost
+ DRAM Manufacturing Cost
```

## 4. 封装 / 组装成本

封装成本反映多个 chiplet 被集成为一个系统的额外开销。这里不再单独建立复杂的 package yield 系数模型，而是优先使用 CATCH 现有封装层的 `cost_per_mm2` 与估算面积结合。

```text
Packaging Cost
= system_chip_count
* estimated_package_area
* package_cost_per_mm2(package_integration_type)
```

其中：

- `estimated_package_area` 是单个 chip 的 package / interposer / substrate 有效面积
- `package_cost_per_mm2` 由 `package_integration_type` 对应的 CATCH 层定义给出
- `system_chip_count` 为系统中 chip 的数量

例如可参考：

```text
organic_substrate -> organic_substrate.cost_per_mm2
silicon_interposer -> combined_interposer_silicon.cost_per_mm2
glass_interposer -> combined_interposer_glass.cost_per_mm2
```

## 5. 互连如何进入成本

在当前这版简化模型中，不再单独定义 `Interconnect Cost`。原因是：

- D2D / C2C 对成本的影响，已经主要通过面积吸收到 `estimated_io_chiplet_area` 中
- 部分 PIM 侧接口逻辑，也可以通过 `estimated_pim_logic_area` 体现
- 如果再额外单列一个互连成本项，容易重复计算

因此更合适的理解是：

```text
D2D / C2C capability
-> more serdes / PHY / switch / buffer
-> larger estimated_io_chiplet_area
-> higher IO manufacturing cost
```

因此，像 `d2d_bandwidth_per_serdes`、`c2c_bandwidth_per_serdes` 这类参数更适合保留在性能/通信模型中，而不是作为成本模型的直接输入。

## 6. 良率相关惩罚

这里不建议追求“真实良率值”的精确建模，而更适合使用一个简单、稳定、可解释的 `yield-related penalty`。

核心思路是：

- 不单独拟合完整的良率模型
- 不额外引入 package yield 或 DRAM yield 的独立系数
- 只保留 logic 侧与工艺和面积直接相关的相对惩罚

### 6.1 Logic yield-related penalty

```text
logic_yield_penalty
= 1 + alpha
* estimated_pim_logic_area
* logic_yield_coefficient_by_process
```

其中：

- `estimated_pim_logic_area` 越大，惩罚越高
- `logic_yield_coefficient_by_process` 越大，惩罚越高
- `alpha` 是一个全局缩放系数，用于控制 yield-related penalty 在总成本中的权重

这里的 `logic_yield_coefficient_by_process` 不需要被理解为真实物理良率参数，而更适合理解为一个由 CATCH `defect_density` 派生出的相对工艺惩罚系数。

### 6.2 `logic_yield_coefficient_by_process` 如何确定

建议通过下面这条路径确定：

```text
logic_process_node
-> 对应 CATCH 的 combined_* layer
-> 读取该 layer 的 defect_density
-> 派生为相对的 logic_yield_coefficient_by_process
```

例如：

- `logic_process_node = 7nm` -> 参考 `combined_7nm.defect_density`
- `logic_process_node = 5nm` -> 参考 `combined_5nm.defect_density`
- `logic_process_node = 3nm_0.001` -> 参考 `combined_3nm_0.001.defect_density`

前期最简单的做法可以是：

```text
logic_yield_coefficient_by_process
= defect_density / defect_density_ref
```

其中 `defect_density_ref` 可以选某个基准工艺，例如 `7nm`。

这样做的目标不是得到真实 yield，而是保留下面这个趋势：

- 更大的 logic die，yield-related penalty 更高
- 更高 defect density 的工艺，yield-related penalty 更高

### 6.3 为什么不单独建 DRAM / package yield

原因很简单：

- CATCH 对 logic process 至少提供了 `defect_density` 这类可借用参考
- 对 DRAM 和 package，当前没有同样稳定、直接、容易解释的对应参数
- 由于 cost 只是 DSE 的一个目标，不值得为此额外建立和验证更复杂的 yield 子模型

因此当前模型中，yield-related penalty 只在 logic 侧显式保留。

## 7. 最终成本公式

综合上面的部分，一个适合 DSE 的最终公式可以写成：

```text
Effective Cost
= (Manufacturing Cost + Packaging Cost) * logic_yield_penalty
```

如果只需要一个归一化分数，不需要真实货币单位，那么所有 cost factor 都可以先用相对系数表示。

例如：

- 以 `7nm logic + organic package + baseline serdes` 作为 1.0 基线
- 其他设计点相对于该基线做归一化比较

## 8. 这个模型最适合捕捉什么 trade-off

这套简化模型最适合捕捉下面几类 DSE 中真正重要的 trade-off：

- chiplet 变小后，yield 上升，但 chiplet 数量更多，封装和互连成本增加
- 更先进的 logic 工艺提升面积效率，但单位面积制造成本更高
- IO / serdes 带宽加大后，性能更强，但互连面积和成本上升
- DRAM 堆叠层数增加后，容量提升，但 stack 成本和 yield 风险上升
- 更复杂的封装方式改善集成能力，但 package base cost 也更高

## 9. 使用建议

- 如果前期缺少真实工艺数据，可以先全部用相对系数。
- 先保证模型能稳定地区分粗粒度和细粒度 chiplet 的成本趋势，再逐步提高精度。
- 不必一开始就追求和真实芯片报价一致，重点是让 cost 作为 DSE 目标时有一致性和可解释性。
