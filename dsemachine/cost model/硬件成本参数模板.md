# 硬件参数成本模板

这份文档用于统一 DSE 中的硬件参数输入，既包含原有的性能/容量相关参数，也包含为了做简化成本评估而新增的成本相关参数。

当前目标不是构建一个特别细粒度的成本模拟器，而是为 DSE 提供一个稳定、可比较不同 design point 的成本模型。

当前成本模型主要覆盖：

- 制造成本
- 良率带来的有效成本变化
- 封装 / 组装成本
- D2D / C2C 互连成本

当前暂不覆盖：

- 测试成本
- NRE 摊销
- 过细的工艺步骤级成本

## 1. 原有硬件参数

### 1. `system_chip_count`

- 类型：`int`
- 含义：整个 system 中包含多少个 chip。
- 作用：决定系统总规模，也会影响系统级 C2C 互连规模和整体封装复杂度。

### 2. `pim_chiplet_per_chip`

- 类型：`int`
- 含义：单个 chip 中集成多少个 PIM chiplet。
- 作用：决定 chip 内部的总容量、总算力和 D2D 连接规模，也会显著影响封装成本和 package yield。

### 3. `pe_layout_m`

- 类型：`int`
- 含义：单个 PIM chiplet 内部 PE 的二维布局中，M 方向上的 PE 数量。
- 作用：和 `pe_layout_n` 一起决定单个 chiplet 内部的 PE 总数，影响算力、面积和片内网络规模。

### 4. `pe_layout_n`

- 类型：`int`
- 含义：单个 PIM chiplet 内部 PE 的二维布局中，N 方向上的 PE 数量。
- 作用：和 `pe_layout_m` 一起决定单个 chiplet 内部的 PE 总数，影响算力、面积和片内网络规模。

### 5. `pe_bank_capacity`

- 类型：`int`
- 含义：单个 bank 的容量。
- 作用：影响每个 PE 的本地存储能力，并最终影响单个 PIM chiplet 的总存储容量。

### 6. `pe_bank_number`

- 类型：`int`
- 含义：单个 PE 拥有多少个 local bank。
- 作用：影响每个 PE 可管理的存储资源规模，也间接影响可提供的带宽能力。

### 7. `pe_memory_controller_number`

- 类型：`int`
- 含义：单个 PE 中配备多少个 Memory Controller。
- 作用：直接影响单个 PE 可并行管理的 memory channel 数量，从而影响带宽，也会带来额外 logic area。

### 8. `pe_systolic_array_m`

- 类型：`int`
- 含义：单个脉动阵列在 M 方向上的规模。
- 作用：影响单个脉动阵列的计算吞吐和面积。

### 9. `pe_systolic_array_n`

- 类型：`int`
- 含义：单个脉动阵列在 N 方向上的规模。
- 作用：影响单个脉动阵列的计算吞吐和面积。

### 10. `pe_systolic_array_number`

- 类型：`int`
- 含义：单个 PE 中集成多少个脉动阵列。
- 作用：决定单个 PE 的总计算能力，也会显著增加 logic die 面积。

### 11. `pe_systolic_array_frequency`

- 类型：`int`
- 单位：`MHz`
- 含义：脉动阵列中基础 MAC 单元的工作频率。
- 作用：影响计算性能。当前可以固定为 `1 GHz`，如果不搜索，可以作为常量配置。

### 12. `d2d_serdes_count_per_pim_chiplet`

- 类型：`int`
- 含义：单个 PIM chiplet 与 IO chiplet 之间的 serdes 数量。
- 作用：决定单个 PIM chiplet 的 D2D 带宽能力，同时也会带来 serdes 面积和封装成本。

### 13. `c2c_serdes_count_per_chip`

- 类型：`int`
- 含义：单个 chip 对外进行 chip-to-chip 通信时可用的 serdes 数量。
- 作用：决定系统级 C2C 带宽能力，也会带来额外 IO / PHY 面积和互连成本。

### 14. `io_chiplet_buffer_capacity`

- 类型：`int`
- 含义：IO chiplet 中 buffer 的容量。
- 作用：当前主要约束 batch feasibility，也会对 IO chiplet 面积有一定影响。

### 15. `dram_channel_timing_profile`

- 类型：`struct` / `config`
- 含义：DRAM channel 的时序和带宽参数集合。
- 作用：决定单个 DRAM channel 能提供的最终带宽。当前可固定，不作为搜索参数。

## 2. 新增成本相关参数

### 16. `logic_process_node`

- 类型：`enum` / `string`
- 示例：`3nm`、`3nm_0.001`、`3nm_0.005`、`3nm_0.01`、`5nm`、`7nm`、`10nm`、`12nm`、`40nm`、`45nm`
- 含义：PIM chiplet 中 logic die 采用的制程节点。
- 作用：决定 logic die 的单位面积制造成本，也会影响逻辑部分的良率和面积效率。

如果希望参考 CATCH 当前已经给出的示例层定义，可以直接对照下面这些选项。它们本质上对应 `CATCH/layer_definitions.xml` 里的 `combined_*` 层，单位面积成本来自其中的 `cost_per_mm2` 字段，单位为 `USD/mm^2`。

- `40nm` -> `combined_40nm` -> `cost_per_mm2 = 0.033497`
- `45nm` -> `combined_45nm` -> `cost_per_mm2 = 0.032171`
- `12nm` -> `combined_12nm` -> `cost_per_mm2 = 0.05636207`
- `10nm` -> `combined_10nm` -> `cost_per_mm2 = 0.084769`
- `7nm` -> `combined_7nm` -> `cost_per_mm2 = 0.132219`
- `5nm` -> `combined_5nm` -> `cost_per_mm2 = 0.25024`
- `3nm` -> `combined_3nm` -> `cost_per_mm2 = 0.29461`
- `3nm_0.001` -> `combined_3nm_0.001` -> `cost_per_mm2 = 0.29461`，`defect_density = 0.001`
- `3nm_0.005` -> `combined_3nm_0.005` -> `cost_per_mm2 = 0.29461`，`defect_density = 0.005`
- `3nm_0.01` -> `combined_3nm_0.01` -> `cost_per_mm2 = 0.29461`，`defect_density = 0.01`

说明：

- 上面这些数值是 CATCH 自带的参考值，不代表权威 foundry 报价。
- 对 DSE 来说，可以先把这些值当作基线，后续再替换成你们自己的相对系数或校准后的数字。

### 17. `io_process_node`

- 类型：`enum` / `string`
- 示例：`40nm`、`45nm`、`12nm`、`10nm`、`7nm`、`5nm`
- 含义：IO chiplet 采用的制程节点。
- 作用：用于单独建模 IO chiplet 的成本。因为 IO / PHY 对先进制程的缩放收益有限，这个参数应与 logic die 分开设置。

CATCH 没有单独提供 “IO 专用工艺节点表”，因此这里通常复用 `combined_*` 层中的逻辑工艺作为近似参考。若你们想表达“IO/PHY 在老工艺更划算”，可以优先从下列节点中选：

- `40nm` -> `combined_40nm` -> `cost_per_mm2 = 0.033497`
- `45nm` -> `combined_45nm` -> `cost_per_mm2 = 0.032171`
- `12nm` -> `combined_12nm` -> `cost_per_mm2 = 0.05636207`
- `10nm` -> `combined_10nm` -> `cost_per_mm2 = 0.084769`
- `7nm` -> `combined_7nm` -> `cost_per_mm2 = 0.132219`
- `5nm` -> `combined_5nm` -> `cost_per_mm2 = 0.25024`

建议：

- 如果 IO chiplet 里以 PHY / serdes / routing 为主，优先把 `40nm`、`45nm`、`12nm`、`10nm` 作为搜索范围。
- 如果只是前期做趋势分析，也可以先让 `io_process_node` 只在 `12nm` 和 `7nm` 两档之间变化。

### 18. `package_integration_type`

- 类型：`enum` / `string`
- 示例：`organic_substrate`、`silicon_interposer`、`glass_interposer`
- 含义：多个 chiplet 被集成在一起时所采用的封装方式。
- 作用：决定 package base cost、组装复杂度和 package yield，是封装成本模型中的关键参数。

口径说明：

- 这里对应的 `cost_per_mm2` 不是乘单个 PIM chiplet 的面积。
- 也不是乘整个 system 的面积。
- 更合理的口径是乘“单个 chip 内封装 / interposer / substrate 需要承载的有效面积”。
- 因此，这个参数应和后面的 `estimated_package_area` 配合使用。

如果希望参考 CATCH 里现成给出的封装层成本，可以对照下面这些层定义：

- `organic_substrate` -> `organic_substrate` -> `cost_per_mm2 = 0.0001`
- `organic_interposer` -> `combined_interposer_organic` -> `cost_per_mm2 = 0.00000053820`
- `silicon_interposer` -> `combined_interposer_silicon` -> `cost_per_mm2 = 0.021905`
- `glass_interposer` -> `combined_interposer_glass` -> `cost_per_mm2 = 0.043910`

说明：

- CATCH 没有直接给出 `fanout` 这样的现成选项，所以如果你们后续想研究 fan-out，需要自己补参数。
- 对你们当前的 DSE，优先使用 `organic_substrate`、`silicon_interposer`、`glass_interposer` 这三类就已经够用了。

### 19. `estimated_package_area`

- 类型：`derived value`
- 含义：估算出的单个 chip 的 package / interposer / substrate 有效面积。
- 作用：作为 `package_integration_type` 中 `cost_per_mm2` 的面积输入。

口径说明：

- 这里要的是 `per chip` 的 package 面积。
- 不是单个 PIM chiplet 的面积。
- 也不是整个系统的总 package 面积。

它通常由下面这些因素推导得到：

- 单个 chip 中 PIM chiplet 的数量
- `estimated_pim_logic_area`
- `estimated_io_chiplet_area`
- DRAM stack footprint
- die 之间的摆放间距、keep-out 区域和 routing margin

建议：

- 在 DSE 中把它作为派生量维护。
- 如果前期没有精确封装 floorplan，可以先用“所有 die footprint 之和乘一个面积放大系数”的方式近似。

### 20. `dram_die_count_per_stack`

- 类型：`int`
- 含义：单个 PIM chiplet 中垂直堆叠的 DRAM die 数量。
- 作用：影响单个 chiplet 的总容量、stack 制造成本以及 stack yield。

如果希望参考 CATCH 中和 memory 更接近的层定义，目前能直接对照的示例比较少，主要是：

- `combined_hbm2_12nm` -> `cost_per_mm2 = 0.1654538`
- `combined_hbm_7nm` -> `cost_per_mm2 = 1.10136`

说明：

- 这两个值在原始 CATCH 中也带有明显的近似性质，不能直接视为可信的 DRAM 报价。
- 对 DSE 而言，`dram_die_count_per_stack` 更建议和一个单独的 `dram_cost_factor` 或 `dram_capacity_cost_factor` 联动，而不是完全依赖这两个示例层。

### 21. `estimated_pim_logic_area`

- 类型：`derived value`
- 含义：估算出的单个 PIM chiplet 中 logic die 面积。
- 作用：作为 logic 制造成本和 logic yield 估算的核心输入。

口径说明：

- 这里要的是 `per die` 的 logic 面积，也就是“单个 PIM chiplet 内那一颗 logic die 的面积”。
- 不是整个 PIM chiplet 的封装占地面积。
- 也不是单个 PE 的面积。

它通常由下面这些已有硬件参数推导得到：

- PE 数量
- systolic array 数量与规模
- memory controller 数量
- 片内 buffer 规模
- D2D 接口逻辑开销
- 片内互连或 NoC 开销

建议：

- 在 DSE 中把它当作派生量，而不是要求用户手工配置一整套面积模型系数。
- 如果前期缺少精确面积模型，可以先用统一的面积估算脚本或经验公式生成。

### 22. `estimated_io_chiplet_area`

- 类型：`derived value`
- 含义：估算出的单个 IO chiplet die 面积。
- 作用：作为 IO die 制造成本估算的核心输入。

口径说明：

- 这里要的是 `per die` 的面积，也就是单个 IO chiplet die 的面积。
- 不是整个 chip 的 package 面积。
- 也不是单个 serdes 或单个 buffer 模块的面积。

它通常由下面这些已有硬件参数推导得到：

- IO buffer 容量
- D2D serdes 数量
- C2C serdes 数量
- switch / router / control logic 开销

其中，D2D / C2C 相关能力对成本的影响，建议主要通过这里体现：

- 更高的 D2D / C2C 带宽需求通常意味着更多或更复杂的 serdes、PHY、switch 和 buffer 资源
- 这些资源会增大 `estimated_io_chiplet_area`
- 随后再由 `estimated_io_chiplet_area` 与 `io_process_node` 对应的 `cost_per_mm2` 一起映射成成本

建议：

- 在 DSE 中把它当作派生量，而不是新增一套必须手工维护的面积参数。
- 如果前期没有独立的 IO 面积模型，可以先采用与 serdes 数量和 buffer 容量相关的简化估算公式。

### 23. `logic_yield_coefficient_by_process`

- 类型：`table` / `dict`
- 含义：不同 logic 制程节点对应的 yield 系数。
- 作用：配合 logic die 面积形成简化 yield 模型，例如面积越大、制程越先进，yield penalty 越高。

这个参数建议和 CATCH 中各工艺层的 `defect_density` 显式对应起来。也就是说：

```text
logic_process_node
-> 选择对应的 combined_* layer
-> 读取该 layer 的 defect_density
-> 再映射成你们自己的 logic_yield_coefficient_by_process
```

如果你们想沿用 CATCH 现成的示例，可以把下面这些层里的 `defect_density` 当作初始参考输入：

- `combined_40nm` -> `defect_density = 0.005`
- `combined_45nm` -> `defect_density = 0.005`
- `combined_12nm` -> `defect_density = 0.005`
- `combined_10nm` -> `defect_density = 0.005`
- `combined_7nm` -> `defect_density = 0.005`
- `combined_5nm` -> `defect_density = 0.005`
- `combined_3nm` -> `defect_density = 0.005`
- `combined_3nm_0.001` -> `defect_density = 0.001`
- `combined_3nm_0.005` -> `defect_density = 0.005`
- `combined_3nm_0.01` -> `defect_density = 0.01`

建议映射关系可以写成：

- `logic_process_node = 40nm` -> 参考 `combined_40nm.defect_density`
- `logic_process_node = 45nm` -> 参考 `combined_45nm.defect_density`
- `logic_process_node = 12nm` -> 参考 `combined_12nm.defect_density`
- `logic_process_node = 10nm` -> 参考 `combined_10nm.defect_density`
- `logic_process_node = 7nm` -> 参考 `combined_7nm.defect_density`
- `logic_process_node = 5nm` -> 参考 `combined_5nm.defect_density`
- `logic_process_node = 3nm` -> 参考 `combined_3nm.defect_density`
- `logic_process_node = 3nm_0.001` -> 参考 `combined_3nm_0.001.defect_density`
- `logic_process_node = 3nm_0.005` -> 参考 `combined_3nm_0.005.defect_density`
- `logic_process_node = 3nm_0.01` -> 参考 `combined_3nm_0.01.defect_density`

说明：

- `defect_density` 是 CATCH 中现成可借用的参考量。
- `logic_yield_coefficient_by_process` 则是你们在 DSE 中真正使用的简化 yield 系数。
- 两者不必数值完全相同，但应该保持单调一致的趋势。


## 3. 建议补充的派生量

下面这些量不一定需要用户手工输入，但建议在 DSE 中自动推导并保存，方便后续统一计算成本：

### `pe_count_per_chiplet`

- 含义：单个 PIM chiplet 中 PE 总数。
- 计算建议：`pe_layout_m * pe_layout_n`

### `sa_count_per_chiplet`

- 含义：单个 PIM chiplet 中脉动阵列总数。
- 计算建议：`pe_count_per_chiplet * pe_systolic_array_number`

### `total_bank_capacity_per_chiplet`

- 含义：单个 PIM chiplet 的总 bank 容量。
- 计算建议：`pe_count_per_chiplet * pe_bank_number * pe_bank_capacity`

### `estimated_package_area`

- 含义：估算出的单个 chip 的 package / interposer / substrate 有效面积。
- 作用：作为封装成本计算的关键输入。

## 4. 使用建议

为了让这个模板更适合 DSE，而不是变成一个过于细的成本模拟器，建议采用下面的原则：

- DRAM 的细时序参数继续固定，不纳入成本搜索。
- `pe_systolic_array_frequency` 主要影响性能，不直接纳入成本模型。
- `dram_channel_timing_profile` 主要影响性能和带宽，不直接纳入成本模型。
- 测试成本和 NRE 暂时忽略。
- 面积相关内容优先保留成派生量，而不是暴露过多难以维护的底层系数。
- 面积模型和 yield 模型保持简洁，优先保留能改变设计点排序的因素。
- 工艺节点、封装类型、chiplet 数量、serdes 带宽和面积估算结果要显式化，因为这些因素最容易影响成本趋势。
