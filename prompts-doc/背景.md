# 论文故事背景

现代 LLM 的规模持续增长。Scaling law 推动模型参数量不断增加，agentic workload 和长上下文应用进一步推高了 KV cache 的存储需求。在 autoregressive decode 阶段，每个 inference step 通常只为每个 request 生成一个新 token，但仍需要反复访问大量模型权重和 KV cache。

因此，LLM decode 的核心瓶颈并不只是计算，而是 resident data 带来的巨大容量和访存带宽需求。对于云侧服务，关键指标是总 tokens/s；对于用户体验，关键指标是 TPOT，即 time per output token。

3D-stacked PIM 是一种适合 LLM decode 的架构方向。它通过 Hybrid Bonding、mini-TSV 等先进封装技术，将多层 DRAM die 与一个 logic die 垂直堆叠。logic die 上的计算单元可以通过高密度垂直互联直接访问 DRAM bank，从而获得远高于传统 off-chip memory 的 bank-level bandwidth。

但是，单个 3D-stacked PIM unit 的容量、带宽和算力都不足以支撑现代 LLM。因此，系统必须集成多个 PIM chiplet。多个 PIM chiplet 与一个 IO chiplet 构成一个 chip，多个 chip 构成一个 node。一个 node 作为完整 LLM instance 的存储和执行单元。

当系统从单个 PIM unit 扩展到 chiplet-based multi-chiplet / multi-chip system 后，性能不再只取决于单个 PIM chiplet 的本地 DRAM 带宽，而取决于：

resident tensor 如何分布在 PIM DRAM 中；

transient tensor 如何在 IO SRAM 中缓存和转发；

input / output / partial sum 如何经过 D2D 和 C2C 流动；

operator tile 如何映射到 chiplet 和 PE；

chiplet 粒度如何影响 yield、interconnect tax 和 utilization；

PE、memory controller、D2D、C2C、SRAM、process node 如何共同决定 PPAC。

因此，本工作需要实现一个 HW/SW co-exploration framework，用于联合搜索硬件架构参数和软件映射策略，在不同场景下找到 PPAC 高效的 Pareto-optimal design points。

# 硬件架构 

Node
 └── Chip(s)
      └── IO Chiplet + PIM Chiplet(s)
             └── PIM Chiplet
                   └── PE(s)
                         └── Local Banks / Memory Channels
## Node
Node 是模拟器中的最大执行单元。

一个 node 包含多个 chip，并完整存储和执行一个 LLM instance。Node 内 chip 之间通过 C2C interconnect 通信。


## Chip
一个 chip 由一个 IO chiplet 和多个 PIM chiplet 组成。

IO chiplet 是 chip 内部的中心化通信和缓冲 hub。它通过 D2D link 连接本 chip 内的 PIM chiplet，通过 C2C link 连接其他 chip 的 IO chiplet。

## IO Chiplet
IO chiplet 是中心化数据流的核心。

IO chiplet 负责：

- 存储 transient tensors；
- 将 input tensor slice 分发给 PIM chiplet；
- 从 PIM chiplet 收集 output tile 或 partial sum；
- 执行 vector operation；
- 执行 softmax；
- 执行 reduction；
- 执行 gather / concat；
- 执行 MoE routing 和 token dispatch；
- 管理 D2D communication；
- 管理 C2C communication；
- 协调 chip 内和 chip 间的数据同步。


默认规则：

```text
Transient tensors 存储在 IO SRAM。
Vector / reduction / softmax / routing 默认在 IO chiplet 执行。
C2C 通信默认只发生在 IO chiplet 之间。
```


## PIM Chiplets
PIM chiplet 是一个 3D-stacked memory-compute unit。

一个 PIM chiplet 包含：

- 一个 logic die；
- 多个堆叠在 logic die 上方的 DRAM die；
- 多个 PE；
- local SRAM buffer；
- memory controller；
- D2D interface；
- PE 间 NoC 或局部互联。

Resident tensors 存储在 PIM chiplet 的 DRAM 中。

PIM chiplet 的主要职责是：

- 存储 weight tile；
- 存储 KV cache shard；
- 从本地 DRAM 读取 resident tensor；
- 执行 matrix / batched matrix tile computation；
- 将 output tile 或 partial sum 通过 D2D 返回 IO chiplet；
- 接收 KV cache update 并写回 DRAM。

默认规则：

```text
PIM chiplet 不直接和其他 PIM chiplet 交换 transient tensor。
PIM chiplet 只和本 chip 的 IO chiplet 通信。
```


## PE、Local Banks 与 Memory Channels

PE 是 PIM chiplet 内部的基本计算单元。

由于 3D 堆叠结构，每个 PE 只能高效访问位于其正上方投影区域内的 DRAM banks。这些 banks 被称为该 PE 的 local banks。

一个 PE 可以包含：

- matrix compute unit，例如 systolic array；
- local SRAM buffer；
- memory controller；
- local bank access path；
- optional vector unit；
- PE-to-PE NoC interface。

每个 PE 的 local banks 被组织成多个 memory channels。

规则：

- 不同 memory channel 可以并行工作；
- 同一个 memory channel 内的多个 banks 共享数据路径；
- 增加 channel 数量可以提高本地带宽；
- 增加 memory controller 数量会提高带宽，但也会增加 area 和 power；
- bank conflict 会影响有效带宽；
- DRAM die 堆叠层数会影响容量和潜在 bank parallelism。


# 基础数据流 
本系统采用以 IO chiplet 为中心的集中式数据流。在 LLM decode 过程中，所有 tensor 被划分为两类：resident tensors 和 transient tensors。Resident tensors 是跨 inference step 长期保留的数据，主要包括 model weights、expert weights 和 KV cache。这类数据容量巨大，因此被静态切分并存储在各个 PIM chiplet 的 DRAM banks 中。Transient tensors 是单个 inference step 内部临时产生并被后续算子消费的数据，包括 activations、Q/K/V intermediates、attention scores、softmax results、partial sums 和 operator outputs。这类数据容量相对较小，因此集中存储在 IO chiplet 的 SRAM buffer 中。

对于矩阵运算或 batched matrix 运算，IO chiplet 首先从 SRAM 中读取 input tensor，并根据 operator-level mapping 将其切分为多个 input slices。随后，IO chiplet 通过 D2D links 将这些 slices 发送到对应的 PIM chiplets。每个 PIM chiplet 从本地 DRAM banks 中读取已经预先放置好的 weight tile 或 KV cache tile，并在本地 PE 上完成 tile-level computation。计算得到的 output tile 或 partial sum 再通过 D2D links 返回 IO chiplet。IO chiplet 在 SRAM 中完成 gather、concat、reduction、softmax 或其他 vector operations，并将结果作为下一个 operator 的 input tensor 继续调度。

当计算需要跨多个 chip 协同时，chip 间通信同样由 IO chiplet 负责。一个 chip 的 IO chiplet 会通过 C2C links 将 transient tensor shard 或 partial result 发送到其他 chip 的 IO chiplet。接收方 IO chiplet 再通过本地 D2D links 将数据分发给其 PIM chiplets 执行计算。因此，PIM chiplet 默认不直接与其他 PIM chiplet 通信，也不直接跨 chip 通信；所有 intra-chip 和 inter-chip 的 transient data movement 都由 IO chiplet 统一协调。

这种数据流设计将 tensor 生命周期与硬件层级对齐：resident tensors 存储在 PIM DRAM，transient tensors 存储在 IO SRAM，matrix-heavy computation 在 PIM PE 上执行，vector / reduction / softmax / routing 在 IO chiplet 上执行，chip 内数据移动通过 D2D 完成，chip 间同步通过 C2C 完成。
