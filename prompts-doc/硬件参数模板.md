下面是搜索的时候和仿真的时候，可以用到的硬件可以配置参数 

1. system 中芯片的个数
    - int 类型 
2. 单个chip 中 PIM chiplet 的数量
    - int 类型
3. PE - M
    - 单个 PIM chiplet 中，PE 是一个 MxN 的 2d layout，这里是 M 的配置
    - int 类型
4. PE - N
    - 同上, 这里是 N 的配置 
    - int 类型
5. PE bank capacity 
    - 单个 bank 的容量 
    - int 类型
6. PE bank number
    - 一个 PE 的 local banks 有多少
    - int 类型 
7. PE MemoryController number
    - 一个 PE 拥有多少个 Memory Controller
    - 决定了带宽的情况 
    - int 类型 
8. PE Systolic Array - M
    - 一个 PE 内部的脉动阵列布局 MxN 个 MAC 单元，这里是M 的值
    - 其实这个就是计算访存比
    - 采取 output stationary 的逻辑，这里的 M 就是 input tensor 的 batch 维度
    - int 类型 
9. PE Systolic Array - N 
    - 这里是脉动阵列的 N 的值 
    - int 类型
10. PE Systolic Array number
    - 这里是一个 PE 中脉动阵列的数量
    - int 类型
11. 单个 PIM chiplet 与 IO chiplet 互联的 serdes 的数量
    - int 类型
    - 带宽相关
    - 这个会同步决定 IO chiplet 的serdes 数量

12. 单个Chip 的对外的 serdes 的数量 (C2C 的数量)
    - int 类型
    - 和芯片之间的带宽直接相关
13. IO chiplet 的 buffer 的容量
    - int 类型
    - 暂时没有什么效果，只决定 batch 的可行性 



# 关于脉动阵列的映射
- 假设 一个 PE 的脉动阵列的尺寸是  SA_M * SA_N *num_SA, 算力是 SA_M * SA_N * num_SA
- 我们采用 OS 策略，基础的 M 维度就是计算访存比
    - 对应到input tensor 的 batch 的维度上
- 对于分给一个 PE 的 compute tile, 输入 tile 是 PE_tile_M, PE_tile_K , weight tile 是 PE_tile_K,PE_tile_N, compute tile 是 (PE_tile_M, PE_tile_K, PE_tile_N). 
    - 我们会将 PE_tile_M 分配到 SA_M 维度上，不满也没办法
    - 剩下的 PE_tile_K * PE_tile_N 会分配到 SA_N * SA_num 维度上
    - 这时，只能继续细分了，按照 SA_N 的尺寸拆开，搞成 block，每个 block 的尺寸是 B_K * B_N, 其中 B_K = SA_num * alpha, B_N = SA_N
    - alpha 是因为DRAM Bank 的 row buffer 激活的问题， 要求对于每个 SA_M * SA_N 的脉动阵列都要维持一个最小的长度，>= page_size/ SA_N
